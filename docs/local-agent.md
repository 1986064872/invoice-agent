# 本地票据 Agent 基础版

## 日期与来源目录更新

本地整理现在支持单月、非连续多个月份（如2025年1月、3月）、全年（2025年）、跨月跨年区间，以及明确的起止日期（2025-01-15至2025-03-02）。这些条件按票面开票日期判断，起止日期均包含边界；不指定日期即不限。

发起新整理请求但未说明位置时，DeepSeek 应先询问发票文件夹完整路径。用户已提供路径或明确说素材目录时直接使用，同一任务的后续条件调整可沿用位置。后端会核对模型传入的路径是否由用户提供；位置缺失、不存在、非绝对路径、整个磁盘、目录连接或符号链接均不启动任务。扫描范围保存到每个任务，不再固定为素材目录。

本地规则模式新增必填文件夹输入框，提供「使用项目素材目录」快捷按钮。计划卡片及任务结果显示实际来源和日期范围。接口的日期字段为 month / months / date_from+date_to，三种形式互斥。AI工具通过 source_dir 传入位置；规则接口通过 source_dir 传入后保存为计划 root。

原票内容理解及自主纠正 OCR 未在本次加入，仍通过原有复核页核对。

入口：启动工具后，打开 `/agent`，或点击侧栏「Agent 工作台」。旧的合成数据演示在 `/agent-demo`。

## DeepSeek 云端对话

页面顶部新增 DeepSeek 对话助手，本地规则模式仍可独立使用。

1. 在 DeepSeek 官方平台创建 API Key，在工作台「DeepSeek API 配置」中填写。默认模型为 `deepseek-flash`，可按账户支持的型号调整。
2. 勾选云端对话的数据发送说明，保存后点击「测试连接」。测试会产生少量真实 API 调用。
3. 发送自然语言需求。模型通过工具生成计划卡片，可继续说「只要某项目的」「排除已入账」「金额至少100元」等来调整。
4. 要求「开始整理」时，模型可直接调用本地工具启动任务，页面自动显示进度。只讨论计划时仍生成计划卡片，也可手动点击开始。
5. 可以在对话中询问进度、查询账本或要求导出。只有正式入账仍需要在台账中勾选确认。

### 对话直接执行

- 「帮我把现在的账本导出」：查询整个账本（默认全部日期、全部状态），实际生成 Excel，在对话区显示下载卡片；明确其中待复核数量，导出不改变状态。
- 「只导出9月已经入账的发票」：模型确定年月，以 confirmed 状态查询后导出。
- 「把这一批的结果给我过目」：当前整理任务完成后，生成仅包含本次匹配票据的审核清单。
- 「开始整理素材里的全部发票，排除已入账」：直接调用本地扫描与 OCR，返回后台任务并在页面显示进度。
- 「把这些导出」：使用本对话前次查询快照生成文件；若票据发生变化，必须重新查询，不能默默导出变化后的集合。

查询支持状态、一个月份或起止日期、进销项、分类和文本关键词；单次最多5000张，页面预览前100张。下载文件保存在本机 exports 目录，使用随机记录 ID 提供下载接口，禁止任意路径读取。查询结果明细仅返回本地页面，模型只收到数量、金额汇总与筛选条件。即使模型在工具执行后超时，已完成的下载卡片和任务 ID 仍返回页面。

对话支持单月、多个月份、日期区间、同时匹配的关键词、购买方或销售方名称包含匹配、是否排除已入账，以及包含边界的价税合计上下限。未接入任意代码执行、删除、自动确认等工具。

API 地址固定为 `https://api.deepseek.com`。密钥仅存于被 Git 忽略的 `data/deepseek.local.json`（本机明文），不会返回给前端，也不写入浏览器存储。也可设置 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，但仍需通过页面启用。密钥留空保存时保留旧值。

对话文字、用户指定的条件及必要任务汇总会发送到 DeepSeek；此对话模块不上传原始图片/PDF、票号、税号或完整票据记录。用户在对话中主动输入的内容会随对话发送。OCR 的数据发送规则不变。

多轮历史保存在本机 `agent_conversation` 表；查询快照、导出记录保存在 `agent_artifact` 表。浏览器保留当前会话 ID，返回工作台或刷新页面时从本机数据库恢复聊天、计划及结果卡片；未发送输入在当前浏览器标签会话内保留。只有点击「新对话」才进入空白会话；旧记录仍留在数据库。单轮最多 6 次模型请求，连接等待上限10秒、响应读取等待默认120秒（可通过 DEEPSEEK_TIMEOUT_SECONDS 配置，范围5至300秒），超时或上游错误不会伪装成规则模式回答。没有真实密钥时只能执行模拟 API 测试，不能宣称已验证云端连接。

## 本地规则模式的使用

1. 在来源位置输入框填写发票文件夹的完整路径，也可点击「使用项目素材目录」。
2. 描述任务，例如「整理素材里的全部发票」「整理2026年9月的发票」「整理上个月包含“公司名”的发票」。
3. 点击「理解任务」，核对开票月份、关键词，再点击「开始查找并整理」。
4. 后台扫描 PDF、JPG、JPEG、PNG，复用已导入的相同文件，对新文件调用现有 OCR、分类和校验流程。
5. 在待审核台账查看结果。点击「查看原票」可在复核页修正；返回后点击「刷新复核结果」。
6. 勾选过目的票据，点击「确认所选并导出 Excel」。有红色错误、信息不足或范围不符的票据不能通过本任务确认。

## 本地规则模式与通用限制

- 采用本地规则解析指令，未接大模型。支持单月、多个月份、全年、日期区间，以及双引号/中文引号内的公司、项目关键词。多个关键词按「同时包含」处理。
- 「上月」「本月」按北京时间解释；只写「9月」使用当前年，执行前显示具体年月。
- 无法解析的文本或复杂约束会返回说明，不默认为全部票据。本地规则模式暂不支持金额范围、排除条件或进销项搜索指令。
- 单次最多读取 50 个 PDF/图片候选、遍历 5000 个文件。超过限制会明确标记结果不完整，不会声称找到全部票据。
- 图片必须先 OCR 才能判断范围。非发票图片可能形成待补录草稿；不匹配草稿保留在票据中心，但不会自动正式入账。
- 原始文件只读，导入时复制到工具的数据目录；不修改或移动原始文件。符号链接、目录连接和其他重解析点被跳过。
- 文件 SHA-256 相同则复用已有票据；不同文件的同一发票继续由原有业务去重规则处理。
- 任务、来源相对路径、结果及执行记录保存到 SQLite 的 `agent_task` 表。刷新恢复最近任务；服务重启会将未完成任务标记为中断，重新整理时复用已有记录。
- 复核页修改后必须刷新任务结果并重新勾选。后端会检查预览版本，避免确认已变化的票据。
- 确认按所选集合事务提交。「确认所选并导出」仅导出所选已确认票据；对话中的账本导出可按请求包含待复核记录，并明确显示状态。下载失败不会撤销已完成的入账。
- OCR 仍遵循现有配置；如配置了云端 OCR，识别文件会按原有流程发送至该服务。

## 验证

`python backend/scripts/agent_check.py` 使用公开合成 PDF 和临时数据库，验证查找、实际解析、复用、任务持久化、筛选、过期预览拦截、确认、Excel 内容范围、扫描限制和源文件保持不变。

前端构建：在 `frontend` 运行 `npm run build`。
